# 联机与终端服务器 — 完整配置指南

本文说明如何把 **Python 终端服务器（GameServer）** 与 **Unity 客户端（含 Mirror 联机）** 配到可稳定联机。请先理解有两类端口，不要混用。

---

## 1. 架构与端口（必读）

| 用途 | 协议 | 默认端口 | 谁监听 | 说明 |
|------|------|----------|--------|------|
| **终端服务器（HTTP API）** | HTTP | **8765** | 你部署的 Linux/Windows 上的 `server.py` | 账号、存档、好友、聊天、联机**信令**、**主机地址登记/解析**、**公开房间号** |
| **Mirror 游戏联机** | **TCP**（Telepathy） | **7777** | **当主机的那台玩家电脑** | 仅联机双方 P2P 直连；需防火墙/路由器放行 |

- 所有玩家只要在 Unity 里把 **Base URL** 指到**同一台**终端服务器的 `http://IP:8765` 即可用好友、邀请、云端地址。
- **不需要**在服务器上开 7777  unless 你故意把 Mirror 也跑在服务器上（本方案**不是**这样设计的）。

## 2. 终端服务器（Python）部署

### 2.1 本机 Windows 快速启动（开发）

1. 进入目录：`Assets/code/GameServer/`（或你工程里含 `start_server.bat` 的 `GameServer` 文件夹）。
2. 双击 **`start_server.bat`**（或先 `stop_server.bat` 再启动）。
3. 脚本会创建 `.venv`、安装依赖、用 **Uvicorn** 监听 **`0.0.0.0:8765`**。
4. 浏览器或可访问机器上访问：`http://本机局域网IP:8765/docs`（若 FastAPI 未关文档）可看到 API。

依赖列表见：`GameServer/backend/requirements.txt`（FastAPI、Uvicorn、bcrypt 等）。

### 2.2 Linux 服务器（局域网或公网）

1. 安装 **Python 3.10+**。
2. 将 `GameServer/backend/` 拷到服务器（至少包含 `server.py`、`requirements.txt`，首次运行后会生成 `data/game.db`）。
3. 建议虚拟环境：

```bash
cd /path/to/backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

4. 启动（对外监听）：

```bash
export PORT=8765   # 可选，默认 8765
uvicorn server:app --host 0.0.0.0 --port ${PORT:-8765}
```

5. **持久运行**可用 `systemd`、`screen`、`tmux` 或 `nohup`，按你运维习惯即可。

### 2.3 数据库与数据目录

- SQLite 默认路径：`backend/data/game.db`（随 `server.py` 所在 `ROOT` 变化）。
- 备份联机与账号数据时，请备份整个 **`data/`** 目录。

### 2.4 反向代理（Nginx / Caddy）与真实客户端 IP

主机「对外 IP 留空」时，登记地址来自 HTTP 连接的 **对端 IP**。若 Unity 只连到 **Nginx**，不配置转发头，服务器可能记下 **内网代理 IP**，好友解析会错。

请在代理上把客户端真实 IP 写入 **`X-Forwarded-For`**（或确保首段为真实公网 IP），后端会取该头**逗号分隔的第一段**。

### 2.5 冷启动会话（按 IP）与 `connection_check`

- 进程内维护 **每个客户端 IP** 最近一次 **任意 HTTP 请求** 的时间；默认 **60 秒**内无请求则下次 `GET /api/connection_check` 返回 **`{"cold_session": true}`**（常量 `COLD_SESSION_IDLE_SEC` 在 `server.py` 可调）。
- Unity 端 **`GameServerSync`** 启动时会先请求该接口；若为冷启动且当前场景不是 **`loadingSceneName`**（默认 `Loadingscene`），会 **Single 加载 Loading 场景** 做账号流程。
- **`connection_check` 失败**（离线等）时客户端按 **冷启动** 处理，同样倾向进入 Loading，避免跳过校验。
- **注意：** 多用户经同一公网 IP / 代理出口时，会共享「最后活动时间」，判定偏粗；精细到设备需另行约定（如设备 ID）。

## 3. Unity 客户端配置

### 3.1 指向终端服务器：Base URL

1. 在场景中找到挂载 **`GameServerSync`** 的物体（或你项目里负责登录的入口）。
2. 在 Inspector 将 **`baseUrl`** 设为：

   - 当前默认：`http://10.24.20.18:8765`（见 `GameServerEndpoint.DefaultBaseUrl`）
   - 本机调试：`http://127.0.0.1:8765`（旧场景会自动升级到新默认）
   - 局域网：`http://服务器局域网IP:8765`
   - 公网（若你开了 HTTPS，则写 `https://你的域名`，并确保证书有效）

3. **所有要联机的人必须使用同一逻辑上的 GameServer**（同一 `game.db` 或同一部署实例），否则账号、好友、邀请不一致。

### 3.1.1 Loading 场景：自动登录与切换账号

- 登录态使用 **`PlayerPrefs`** 保存 token（与用户名），**不**默认保存明文密码；再次进入 **`Loadingscene`** 且勾选 **`MenuLoginPortalFlow.skipLoginIfAlreadyLoggedIn`** 时，会先请求 **`/api/player_state`** 校验 token，成功则跳过登录表单，进入「点击进入游戏」阶段。
- **「切换账号 / 登出」**：准备进入游戏时会显示含 **`(P)`** 的说明文案（可改 **`switchAccountHintLine`**）；按键盘 **`P`**（Inspector 里 **`switchAccountKey`**）登出并回到登录面板。不使用按钮，避免与「点击进入游戏」的鼠标判定冲突。若使用自建 **`enterGameHintRoot`**，可在其下加子物体 **`SwitchAccountHint`**（带 **`Text`**）或指定 **`switchAccountHintLabel`**。
- **`GameServerSync`** 上 **`loadingSceneName`** 须与 Build Settings 中 Loading 场景名一致。

### 3.2 Mirror 与联机预制体

1. 确认 `Packages/manifest.json` 已通过 **OpenUPM** 安装 **`com.mirrornetworking.mirror`**（详见主 `README.md` 联机章节）。
2. Unity 菜单：**Tools → 联机 → Create Coop Player Prefab**，生成 **`Resources/CoopPlayer.prefab`**（内含 **`CoopPlayerRoomStats`**（右上角人数）、**`CoopQuestStateHub` / `CoopQuestRelay`**（共享房主任务进度）；若你已有旧预制体，请**重新执行一次**该菜单或从仓库拉取最新预制体以更新组件）。
3. **一键场景配置（推荐）：** 菜单 **Tools → 联机 → 一键配置联机服务** —— 会创建或更新 **`Multiplayer_Services`**（含 `MultiplayerHubController` + `MultiplayerEntryToggle`，热键 **K**），自动清空自定义 Panel Root、启用运行时 UI、尝试引用 `CoopPlayer`；若场景已有 **`GameServer_Network`**，会挂在其下以便随 **`GameServerSync`** 跨场景，否则会为本物体加 **`MultiplayerServiceRoot`** 做 `DontDestroyOnLoad`。
4. 场景中 **不要** 与别的 `NetworkManager` 冲突；联机会创建或使用 **`LanCoopNetworkManager`**。

### 3.3 联机端口（Mirror）

- 在 **`MultiplayerHubController`** 上检查 **`mirrorPort`**（默认与 **`LanCoopNetworkManager.networkPort`** 一致，常为 **7777**）。
- 改端口时：**主机与客户端信令中的端口必须一致**；云端登记也会用该端口。

### 3.4 联机面板与「对外 IP」

- 通过 **`MultiplayerEntryToggle`**：默认按 **`K`** 开关面板（可在 Inspector 修改 `toggleKey` / 关闭 `enableHotkey`），或 UI 按钮绑定 **`Toggle()`** 打开 **`MultiplayerHubController`**。脚本需挂在**始终激活**的物体上（例如与 `GameServerSync` 同级）才能收到按键。
- **`MultiplayerHubController`** 打开联机面板时，默认会**暂时隐藏**除联机 Canvas 以外的所有 **Screen Space Overlay / Camera** 的 Canvas（不处理 **World Space**）；关闭面板或组件被禁用时**恢复原激活状态**。可在 Inspector 取消 **`Hide Other Screen Space Canvases When Open`**，或在 **`Extra Roots To Hide When Panel Open`** 里额外指定要隐藏的根物体（如准星父节点）。
- **房间在线人数（右上角）：** 联机会话进行中（`CoopSessionState.InSession`）时显示「房间在线：N 人」；人数来自 Mirror **`numPlayers`**（已生成玩家数），由主机玩家上的 **`CoopPlayerRoomStats`** 经 SyncVar 同步。请确保 **`Resources/CoopPlayer.prefab`** 已用菜单 **Tools/联机/Create Coop Player Prefab** 重新生成并包含该组件。
- **任务与寝室币（房主权威）：** 主机玩家上的 **`CoopQuestStateHub`** 将房主 **`QuestSystemManager`** 快照同步给客端；客端可用 **`J`** 看同一任务进度并帮房主推进（到达点/事件等经 Command 在主机执行）。客端断线后会从 HTTP 拉回**本人**存档；寝室商城购买仅房主扣币（客端会提示不可购买）。
- **按 K 没反应（从菜单 / Loading 进关后）**：`MultiplayerHubController` 若只放在 **Loading 或菜单场景**里，`LoadScene` 单场景加载后会被卸掉，热键找不到面板。处理：**①** 用 **Tools → 联机 → 一键配置**，把 **`Multiplayer_Services` 挂在 `GameServer_Network` 子物体**上（随 `DontDestroyOnLoad` 保留）；**②** 或把联机组件做进**每个关卡场景**；**③** 现版本在按 K 时若仍找不到 Hub，会尝试在 **`GameServerSync` 所在物体上自动添加 `MultiplayerHubController`**（并打一条 Console 说明），一般按一次 K 即可出现面板，但长期仍建议用一键配置固定结构。另请确认 **`GameServerSync` 勾选 `Dont Destroy On Load`**，且 **`Poll Multiplayer Panel Hotkey Here`** 为开启。
- **当主机时**，「**对外 IP（可选）**」：
  - **留空**：服务器用你访问 HTTP 时看到的 IP（经代理时请配好 `X-Forwarded-For`）。
  - **填写**：用于公网 IP、或局域网内指定网卡 IP 等，避免自动识别错误。

## 4. 操作系统与路由器防火墙

### 4.1 当主机的 Windows 电脑

- **入站**：放行 **TCP `mirrorPort`（默认 7777）**（Mirror Telepathy）。
- **出站**：一般无需改；若公司网络限制出站，需放行对你伙伴 IP 的 TCP 7777。

### 4.2 终端服务器（8765）

- 若客户端跨网访问：防火墙/安全组放行 **TCP 8765**（或你改的 `PORT`）。

### 4.3 跨互联网（NAT）

- 访客无法直连你内网 IP，需在**主机侧路由器**做 **端口转发**：外部 TCP **7777** → 主机内网 IP 的 **7777**。
- 云端登记的 IP 应为 **公网 IP**（或在「对外 IP」里手动填公网 IP）。

## 5. 联机操作步骤（标准流程）

以下假设：**A = 邀请方（客人）**，**B = 同意邀请并当主机的一方**。

1. **A、B 均登录**同一终端服务器上的账号（`GameServerSync` 已登录）。
2. **加好友**（面板内发申请、对方用 request id 同意）。
3. **A** 点击向好友发 **联机邀请**。
4. **B** 在「待处理联机邀请」里看到邀请，记下 **邀请 id**，填入输入框，点 **「同意并当主机」**。
5. **B** 本机 **Mirror 起 Host**，并向服务器 **publish** 主机地址；随后 HTTP 信令里写入连接信息。
6. **A** 端自动轮询 **outstanding**；拿到信令后优先 **`/api/coop/host/resolve`** 查 **B 的 user_id** 对应的 IP:端口，失败再用信令 JSON。
7. **A** 作为 **Client** 连接 **B** 的 IP:端口。
8. 结束联机时双方使用面板 **「停止联机」**；主机会 **unpublish** 并停 Mirror。

**注意：** 设计约定为 **同意邀请的一方 = 主机**（世界权威在 B）。

### 5.1 公开房间号（无需好友）

双方仍须 **登录同一台终端服务器**；区别是 **不必加好友、不必走邀请 id**。

1. **房主**：联机面板点 **「创建公开房间号」**，记下 **6 位字母数字**（不含易混的 0/O、1/I），发给对方（聊天软件等均可）。
2. **房主**：点 **「启动主机并绑定房间号」** —— 本机 Mirror 起 Host，并向服务器登记 **IP:端口** 与该房间号绑定；之后约 **每 45 秒** 自动续期（与好友主机登记类似）。
3. **客人**：在 **「输入对方房间号加入」** 里填房间号，点 **「加入公开房间」** —— 客户端会轮询解析，待主机上线后自动 **Mirror Client** 连接。
4. **结束**：房主点 **「停止联机」** 会 **关闭** 该公开房间记录并 **unpublish** 好友侧主机登记；客人停止联机只断开 Mirror。

**跨网与防火墙** 与好友联机相同：主机放行 **TCP 7777**，路由器按需 **端口转发**；「对外 IP」仍用于修正云端登记的地址。公开房间记录 **TTL 约 30 分钟**，绑定/续期会刷新过期时间。

## 6. 与联机相关的 HTTP API（便于自检）

在服务器可访问的前提下，可用浏览器或 `curl` 配合已登录拿到的 `token` 排查（具体以 `server.py` 为准）：

- `GET /api/connection_check`（**无需 token**，返回 `cold_session`：该 IP 是否超过空闲阈值未访问）
- `GET /api/friends/list?token=...`
- `GET /api/coop/pending?token=...`
- `GET /api/coop/invite/outstanding?token=...`
- `POST /api/coop/host/publish`（body: `token`, `port`, `advertised_address`, `transport`）
- `GET /api/coop/host/resolve?token=...&host_user_id=...`
- `POST /api/coop/public-room/create`（body: `token`）→ 返回 `room_code`
- `POST /api/coop/public-room/bind`（body: `token`, `room_code`, `port`, `advertised_address`, `transport`）
- `GET /api/coop/public-room/resolve?token=...&room_code=...`（**不校验好友**）
- `POST /api/coop/public-room/close`（body: `token`, `room_code`）

好友主机登记 **TTL 约 120 秒**；公开房间 **TTL 约 1800 秒**。客户端当主机时约 **每 45 秒** 续期；超时后 resolve 会 `has_host: false`（或公开房间 `has_room: false`）。

## 7. 配置检查清单（成功标准）

- [ ] 终端服务器 `uvicorn` 监听 `0.0.0.0:8765`（或你改的端口），客户端 `baseUrl` 与之完全一致（含 `http://`、无多余尾部 `/` 亦可，`GameServerSync` 会自动 trim）。
- [ ] 所有客户端能 **注册/登录**，且好友列表、聊天正常（证明 HTTP 与 token 正常）。
- [ ] **B** 当主机时，本机 **TCP 7777 入站**已放行；跨网则 **路由器已转发 7777**。
- [ ] **B** 在面板填写的「对外 IP」或服务器解析出的 IP，对 **A** 而言 **路由可达**（同一局域网或可从公网访问该 IP 的 7777）。
- [ ] 已生成 **`Resources/CoopPlayer.prefab`**，且无其它 `NetworkManager` 抢 `singleton`。
- [ ] 使用 **停止联机** 结束会话，避免主机登记长期残留（虽有过期时间）。

## 8. 常见问题

**Q：客人一直「等待联机同意超时」**  
A：确认 B 已点同意并完成 Host；双方是否同一服务器；A 是否在用正确的邀请轮询；网络是否阻断 HTTP。

**Q：能登录但 Mirror 连不上**  
A：区分 8765 与 7777；检查 Windows 防火墙、路由器转发、B 的「对外 IP」是否为 A 能访问的地址。WA
